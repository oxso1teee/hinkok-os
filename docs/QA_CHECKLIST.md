# Manual QA checklist (release readiness, section 20)

Run by hand before each major release. This is not automated — `npm run
e2e`/`e2e-local` cover the same ground at the code level, but this table is
the human pass across real devices, per `docs/RELEASE_READINESS_PROMPT.md`
section 20.

**Status legend**: ✅ = verified in this session (desktop/API-level, see the
note); ⬜ = genuinely needs a human on a real device/account — nothing this
session's sandbox could substitute for. A ✅ here means the underlying
behavior is confirmed to work; it does **not** replace the ⬜ rows that need
a real phone, a real Telegram app, or a real third-party account — do those
before calling a release done.

## Что физически не может закрыть агент без вашего участия

Каждая строка ⬜ выше требует одного из:
- реального устройства (iPhone/Android/iPad),
- реального стороннего аккаунта (Telegram-бот, Google, GitHub PAT + заполненный vault, OpenAI с работающим ключом, Sentry, аптайм-сервис),
- запуска против реального прод-домена с реальными секретами,
- явно деструктивного/необратимого действия (ротация секрета, force-push, rollback), которое агент не выполняет без вашего прямого разрешения на каждое конкретное действие.

Строки ✅ — это уверенность в том, что код и логика работают корректно, проверено
эмпирически (не просто прочитан код), но не заменяет реальный прогон на настоящих
устройствах/сервисах перед тем, как считать релиз полностью готовым.
